# Auto Memory

Auto Memory 让 Dock 跨会话记住用户的偏好、纠正和项目背景。它就是一个 Markdown 文件夹，加上
提示词里一段说明，模型用普通的 Read、Write、Edit 读写，没有专门的记忆工具，也没有向量库。

## 存放位置

```text
~/.dock/projects/<仓库>/memory/
├── MEMORY.md          # 索引，一条记忆一行
├── user_role.md       # 一条记忆一个文件
└── ...
```

目录按 Git 仓库划分，同一个仓库的子目录和 worktree 共用一份。可以用 `autoMemoryDirectory`
指定其他位置。

## 加载

每次会话只把 `MEMORY.md` 放进上下文，最多 200 行或 25000 字节，超出部分不加载，并提醒模型
精简索引。具体的记忆文件不预加载，模型从索引判断相关时再去读。

索引常驻、正文按需，记忆再多，每轮固定占用的上下文也只有一份索引。

## 记什么

每条记忆是一个带 frontmatter 的文件，`type` 只有四种：

- `user`：用户是谁，专长和偏好；
- `feedback`：用户的纠正和认可过的做法，附上原因；
- `project`：从代码和 Git 里看不出来的进行中工作、约束和决定；
- `reference`：外部资源在哪里。

写入分两步：先写记忆文件，再在 `MEMORY.md` 里加一行指针。写之前先检查有没有可以更新的
已有记忆。

不记的内容：代码结构、文件路径、Git 历史、`AGENTS.md` 里已有的内容，以及只对当前对话有用的
细节。这些要么能从仓库里直接查到，要么很快就会过时。用户说"记住"时立即保存，说"忘掉"时
删除或改正。

## 防止过时

- 记忆文件每次写入时，Dock 会在 frontmatter 里更新 `modified` 时间。
- 提示词要求模型把回忆出来的内容当作可能过时的信息：记忆里提到的文件、函数和配置，依据它
  行动之前先核实当前状态。
- `MEMORY.md` 接近或超过上限时，写入结果会提醒模型精简索引。

## 后台补记

一个由用户发起的回合正常结束后，Dock 会在后台回看这段新对话，补记值得长期保存的信息：

- 如果主 Agent 在这段对话里已经写过记忆，就跳过，两者不会重复记录；
- 后台任务复用主对话的上下文前缀，只能读文件，只能写记忆目录，Bash 只允许只读命令，最多 5 轮；
- 只有成功完成，才会推进"已处理到哪条消息"的位置，失败的部分下次还会再看。

## 关闭

```json
{ "autoMemoryEnabled": false }
```

关闭后不注入说明和索引，也不运行后台补记。`dock -p --no-memory` 只对本次运行关闭。

子 Agent 默认不加载主对话的记忆；以 fork 方式派出的子 Agent 继承了整段对话，因此例外。
