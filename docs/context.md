# 上下文与压缩

## 项目指令

Dock 在会话开始时加载 `~/.dock/AGENTS.md`，以及从项目根目录到当前目录每一级的 `AGENTS.md`。
指令中独占一行的 `@path` 会展开对应文件，最多嵌套四层。

这些内容和 Auto Memory 的索引一起，作为对话最前面的一条上下文放进每次请求，而不是写进
system prompt。会话中途修改 `AGENTS.md` 不会立刻生效，要等下一次压缩或新会话：这样请求
前缀保持不变，模型提供方的 prompt cache 才能持续命中。

## 自动压缩

对话接近上下文上限时，Dock 让模型把历史写成一份结构化摘要，用摘要代替原来的对话，然后
继续工作。每次请求模型之前检查一次：

```text
阈值 = contextWindow − min(maxOutputTokens, 20000) − 13000
```

20000 留给摘要本身的输出，13000 是缓冲。默认配置下（200000 窗口）阈值是 167000。

当前用量的估算方式：取上一次请求的真实输入 token 数（包括缓存读写的部分），再加上之后新增
内容按字符数粗略估算的部分。大头是 provider 返回的真实值，粗估只覆盖最后一小段，每次请求
后又被真实值校正。

## 摘要怎么生成

摘要请求和主对话使用同一个前缀：同样的 system prompt、工具定义和历史，末尾追加一条摘要
指令，因此能复用主对话的缓存。这次请求只生成一次回复，不执行任何工具。

摘要按固定的几节组织：用户的请求和意图、关键概念、涉及的文件和代码、错误和修复、所有用户
消息、待办、当前工作、下一步。模型先写一段分析草稿，再写正式摘要，草稿不会保留。

`/compact 关注点` 可以手动压缩，并让摘要侧重指定的内容。

## 压缩后恢复什么

摘要会丢掉细节，所以压缩之后 Dock 会把正在用的材料放回来：

- **最近读过的文件**：最多 5 个，从磁盘重新读取当前内容。单个文件超过约 5000 token 时只给出
  路径，总量不超过约 50000 token。重新读取同样经过权限检查。
- **用过的 Skills**：每个最多约 5000 token，总量约 25000 token，截断时保留开头并注明完整文件的
  位置，详见 [Skills](skills.md#压缩之后)。
- **项目指令和 Memory 索引**：从磁盘重新加载，会话中途对它们的修改在这时生效。

TUI 中仍然显示完整的历史，只有发给模型的上下文被替换。

## 失败处理

摘要请求本身也可能超出上下文。这时 Dock 按"一次请求和它的回复"为单位，从最早的部分开始
丢弃，再重试，最多重试 3 次。

自动压缩连续失败 3 次后，本会话不再自动压缩，避免每一轮都花掉一整段上下文去重复失败的请求。
手动 `/compact` 仍然可以使用，一次成功的压缩会恢复自动压缩。

## 清理旧工具结果

距离上一次模型回复超过 60 分钟时，Dock 会把较早的工具结果正文替换成一句"已清理"，只保留
最近 5 个。只处理 Read、Bash、Grep、Glob、Write、Edit 的结果，工具调用本身保留。

离开这么久之后，provider 端的 prompt cache 已经过期，下一次请求本来就要重新处理整个前缀；
趁这时去掉旧结果，不会额外破坏缓存。清理会记入会话文件，恢复会话后看到的是同样的上下文。

```json
{
  "contextManagement": {
    "toolResultClearing": { "enabled": true, "gapThresholdMinutes": 60, "keepRecent": 5 }
  }
}
```
